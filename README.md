# 게임 타이머 (GameTimer)

아들의 주간 게임 시간을 관리하는 개인용 앱. 주마다 기본 게임 시간을 정해 두고,
한 주 동안 **차감(패널티)** / **추가(베네핏)** 버튼으로 남은 시간을 조정한다.

**두 가지 버전이 있다. 화면과 동작은 같다.**

| | 웹앱 (`docs/`) | 네이티브 (`GameTimer/`) |
| --- | --- | --- |
| 설치 | 사파리에서 **홈 화면에 추가** | Xcode + USB 케이블 |
| 필요한 것 | 없음 | Mac, Apple ID, (USB 페어링) |
| 만료 | **없음** | 무료 계정은 7일마다 재서명 |
| 본인 확인 | Face ID(WebAuthn) + 예비 PIN | Face ID(LocalAuthentication) + 기기 암호 |

회사 Mac의 보안 정책으로 USB 페어링이 막혀 있어 **웹앱이 실제로 쓰는 버전**이다.
네이티브 판은 Mac을 쓸 수 있게 되면 그대로 쓸 수 있도록 남겨 둔다.

- 남은 시간 = `주간 기본 시간 + 이번 주 추가 합계 − 이번 주 차감 합계`
- 주 시작일(월요일/일요일 선택)이 되면 자동으로 기본 시간으로 초기화된다. 지난 주 기록은 그대로 남는다.
- 네트워크를 쓰지 않는다. 모든 데이터는 아이폰 안에만 저장된다.

## 화면

| 화면 | 내용 |
| --- | --- |
| 메인 | 남은 시간(`06:45`)과 2열 버튼(차감 / 추가). 화면 비율에 따라 배치가 바뀐다 — 아래 참고 |
| 기록 | 주별 → 일별로 묶은 차감/추가 내역. 행을 왼쪽으로 밀면 삭제(실수로 누른 것 되돌리기) |
| 설정 | 주간 기본 시간, 주 시작 요일(월/일), 차감·추가 항목 추가/편집/삭제/순서 변경 |

### 잠금 (Face ID)

시간에 영향을 주는 동작은 전부 **Face ID / Touch ID / 기기 암호**로 본인 확인을 받는다.
아이가 몰래 시간을 늘리거나 이미 받은 차감을 지우지 못하게 하는 것이 목적이라, 우회로가 없도록
세 길목을 모두 막았다.

| 동작 | 잠금 |
| --- | --- |
| 차감 / 추가 버튼 누르기 | 필요 |
| 기록에서 항목 삭제 (스와이프) | 필요 — 지우는 것도 시간을 되돌리는 일이다 |
| 설정 화면 열기 | 필요 — 기본 시간과 항목을 바꾸면 잔여 시간이 달라진다 |
| 기록 화면 보기 | 불필요 (읽기 전용) |

생체 인식만 요구하지 않고 **기기 암호까지 허용**한다(`LAPolicy.deviceOwnerAuthentication`).
얼굴을 몇 번 못 알아보면 생체 인식이 잠기는데, 그때 앱을 아예 못 쓰게 되는 상황을 막기 위해서다.

기기에 암호가 아예 설정되어 있지 않으면 확인할 수단이 없으므로 잠금 없이 통과시킨다.
막아 버리면 앱을 영영 못 쓰게 되는 데다, 기기 자체에 잠금이 없다면 지킬 경계도 없기 때문이다.
따라서 **아이폰에 암호가 설정되어 있어야 잠금이 실제로 걸린다.**

> 시뮬레이터에서 확인하려면 Features → Face ID → Enrolled를 켠 뒤, 프롬프트가 뜨면
> Features → Face ID → Matching Face(성공) / Non-matching Face(실패)를 고른다.

차감과 추가는 색이 아니라 **모양**으로 구분한다. 차감은 꽉 채운 버튼, 추가는 테두리만 있는 버튼이다.
전체가 회색조라 라이트/다크 모드 어느 쪽에서도 그대로 동작한다.

### 아이폰 / 아이패드

| | 방향 | 메인 화면 배치 |
| --- | --- | --- |
| 아이폰 | 세로 고정 | 위: 남은 시간 / 아래: 2열 버튼 |
| 아이패드 | 가로 고정 | 왼쪽: 남은 시간 / 오른쪽: 2열 버튼 |

배치는 기기 종류가 아니라 **실제 화면 비율**로 정한다(가로가 세로보다 길면 좌우 배치).
아이패드에서는 시간 글자와 버튼이 화면 크기에 맞춰 함께 커진다.

아이패드를 세로로 들면 앱이 가로로 고정된 채 위아래에 검은 여백이 생긴다. 가로로 돌리면 꽉 찬다.
가로 고정을 실제로 강제하려면 `UIRequiresFullScreen`이 필요해서, 그 대가로 **아이패드 Split View/Slide Over는 쓸 수 없다**.


## 웹앱 (실제 사용 버전)

`docs/` 폴더가 곧 앱이다. 빌드 단계가 없고 정적 파일뿐이라 GitHub Pages에 그대로 올라간다.

```
docs/
  index.html          화면 뼈대
  app.css             회색조 스타일, 세로/가로 배치 전환
  app.js              화면 렌더링과 동작
  core.js             주 계산 · 원장 · 표시 문자열 (순수 함수, 테스트 대상)
  store.js            localStorage 저장 + 백업 내보내기/불러오기
  auth.js             Face ID(WebAuthn) + 예비 PIN
  sw.js               오프라인 캐시
```

### 아이패드/아이폰에 설치하기

1. 사파리로 앱 주소를 연다.
2. 공유 버튼 → **홈 화면에 추가**.
3. 홈 화면 아이콘으로 실행하면 사파리 UI 없이 전체 화면으로 뜬다.
4. 첫 실행에서 **Face ID를 등록**하고 **예비 PIN**을 정한다.

케이블도, 개발자 계정도, 7일마다 재서명도 필요 없다. 사용법 유도(키오스크)도 네이티브와 똑같이 걸린다.

### 개발

```sh
node --test tests-web/core.test.mjs    # 주 계산 · 원장 · 포맷 테스트
python3 -m http.server 8765 -d docs    # http://127.0.0.1:8765 에서 확인
```

`docs/`의 파일을 고친 뒤에는 `docs/sw.js`의 `CACHE` 이름 숫자를 올려야 기기에서 새 버전을 받는다.

### 알아둘 점

- **Face ID는 HTTPS 주소에서만 동작한다.** 로컬 `http://`로 열면 예비 PIN만 쓸 수 있다.
- WebAuthn 서명을 검증하는 서버가 없으므로 암호학적 강제가 아니라 **기기 소유자 확인** 수준이다.
  네이티브 판의 LocalAuthentication도 같은 성격이고, 사용법 유도로 고정된 아이패드에서는
  아이가 개발자 도구를 열 수단이 없다.
- 데이터는 **기기 안에만** 남는다. 서버로 전송되지 않는다.
- 홈 화면에 추가한 웹앱은 자체 사용 카운터를 가져 사파리 탭보다 데이터가 오래 보존되지만,
  저장공간이 부족하면 지워질 수 있다. **설정 → 백업 → 내보내기**로 가끔 파일을 남겨 두면 안전하다.
- 웹앱은 시스템 밝기를 바꿀 수 없어 네이티브의 유휴 디밍이 없다. 전용 기기라면 제어 센터에서
  밝기를 한 번 낮춰 두면 된다.

## 아이패드를 게임 타이머 전용 기기로 쓰기

아이패드를 이 앱에만 고정해서, 아이가 앱을 닫고 다른 기능을 쓰지 못하게 할 수 있다.
**앱이 하는 일이 아니라 iOS의 "사용법 유도"(영문 Guided Access) 기능**이다. iOS는 서드파티 앱이 스스로를
전면에 고정하는 것을 허용하지 않으므로, 이 방법이 정식 경로다.

### 준비 (한 번만)

1. 설정 → **손쉬운 사용** → 맨 아래로 스크롤 → **사용법 유도** → 켜기
   (설정 검색창에 "사용법 유도"를 입력하면 바로 찾을 수 있다. 영문은 Guided Access.)
2. 그 안의 **암호 설정** → 사용법 유도 암호를 정하고, **Face ID 토글을 켠다**
   (이걸 켜야 얼굴로 빠져나올 수 있다. 안 켜면 매번 암호를 눌러야 한다)

### 쓰는 법

| | |
| --- | --- |
| 시작 | 게임 타이머를 연 상태에서 **상단 버튼 3번 연속 클릭** → 시작 |
| 종료 | **상단 버튼 3번 클릭 → Face ID** |

시작하면 홈 화면으로 나가기, 앱 전환, 제어 센터가 모두 막히고 화면에는 이 앱만 남는다.

### 버튼까지 막고 싶다면 (선택)

사용법 유도 시작 화면에서 **차감/추가 버튼 영역을 손가락으로 동그라미 치면** 그 부분의 터치가 꺼진다.
가로 배치에서는 화면 오른쪽 절반이다. 아이가 버튼을 눌러 Face ID 창을 계속 띄우는 것을 막을 수 있고,
아이는 남은 시간만 보게 된다. 시간 조정은 부모가 아이폰에서 하거나, 사용법 유도를 잠깐 풀고 한다.

### 화면을 오래 켜 두는 것에 대해

아이패드에 암호가 걸려 있으면(이 앱의 Face ID 보호가 동작하려면 필요하다) 자동 잠금 후에 아이가
스스로 깨울 수 없다. 그래서 전용 기기는 화면을 계속 켜 두게 되는데, 그때를 위한 대비가 들어 있다.

**앱이 알아서 하는 것** (아이패드에서만 동작. 아이폰은 자동 잠금이 알아서 하고, 손에 들고 쓰는 기기에서
밝기가 멋대로 바뀌면 성가시므로 제외했다.)

- **픽셀 시프트**: 화면 내용을 2분마다 3pt씩 네 방향으로 옮긴다. 눈에 띄지 않는다.
  LCD에서는 번인이 사실상 없어 당장 필요하진 않지만, 비용이 없고 나중에 OLED 기기로 바꿔도 그대로 대비된다.
- **유휴 디밍**: 2분간 아무도 손대지 않으면 **화면 밝기를 실제로 낮춘다**(12%).
  아무 곳이나 터치하면 원래 밝기로 돌아오고, 어두운 상태의 첫 터치는 깨우는 데만 쓰여 버튼이 눌리지 않는다.
  앱이 배경으로 나가면 밝기를 반드시 되돌린다.

화면 위에 반투명한 막을 씌우는 흔한 방식은 쓰지 않았다. **LCD는 백라이트가 그대로 켜져 있어서
전력·발열·수명에 아무 도움이 안 되기 때문이다.** 실제로 줄이려면 시스템 밝기를 건드려야 한다.

**직접 설정할 것** (이쪽이 효과가 더 크다)

- **밝기를 낮춰 둔다.** 전용 기기라면 제어 센터에서 한 번 낮춰 두면 된다. 백라이트 수명과 발열에 가장 큰 요인이다.
- **자동 밝기**를 켠다 (설정 → 손쉬운 사용 → 디스플레이 및 텍스트 크기 → 자동 밝기).
- **24시간 충전기에 꽂아 두지 않는다.** 배터리를 계속 100%로 두면 수명이 준다.
  최신 기기라면 설정 → 배터리 → 충전 제한을 80%로 두는 편이 낫다.

### 한계

**사용법 유도 세션은 재부팅하면 풀린다.** 아이가 전원을 껐다 켜면 홈 화면으로 나올 수 있다. 보완하려면:

- **스크린 타임** (설정 → 스크린 타임 → 콘텐츠 및 개인정보 보호 제한)으로 다른 앱과 기능을 따로 막는다.
  재부팅과 무관하게 유지되므로 사용법 유도과 같이 쓰면 구멍이 메워진다.
  **스크린 타임 암호는 기기 잠금 암호와 다르게** 정해야 의미가 있다.
- 재부팅 우회까지 확실히 막아야 하면, 무료 앱인 **Apple Configurator**로 아이패드를 감독(supervised) 기기로
  만들고 **단일 앱 모드**를 건다. 재부팅에도 유지되지만 **아이패드가 초기화되고**, 풀 때마다 Mac에 연결해야 한다.

## 네이티브 앱을 아이폰에 설치하기

1. **Xcode**를 실행하고 `GameTimer.xcodeproj`를 연다. (스킴은 처음 열 때 자동으로 만들어진다.)
2. **번들 ID.** 현재 `com.js100.GameTimer`로 설정되어 있다. App ID는 전 세계에서 겹치면 안 되므로,
   혹시 "already in use" 오류가 나면 타겟 `GameTimer` → **Signing & Capabilities** →
   Bundle Identifier를 다른 값으로 바꾼다. (예: `com.본인아이디.GameTimer`)
3. **Apple ID를 등록한다.** Xcode → Settings → Accounts에서 Apple ID를 추가한다.
   유료 개발자 계정이 없어도 **Personal Team**으로 설치할 수 있다.
4. 같은 화면에서 **Automatically manage signing**을 켜고 Team을 방금 추가한 Personal Team으로 고른다.
5. 아이폰을 케이블로 연결하고 "이 컴퓨터를 신뢰하시겠습니까?"에 **신뢰**를 누른다.
6. 아이폰에서 **개발자 모드**를 켠다: 설정 → 개인정보 보호 및 보안 → 개발자 모드 → 켜기 → 재부팅.
   (이 항목은 Xcode가 기기를 한 번 인식한 뒤에 나타난다.)
7. Xcode 상단에서 실행 대상으로 본인 아이폰을 고르고 **Run(⌘R)**.
8. 첫 실행은 막힌다. 아이폰에서 설정 → 일반 → VPN 및 기기 관리 → "개발자 앱" 아래의 본인 Apple ID →
   **신뢰**를 누른 뒤 다시 실행한다.

### 무료 계정으로 쓸 때 알아둘 점

- 서명이 **7일**만 유효하다. 앱이 안 열리면 아이폰을 연결하고 Xcode에서 Run만 다시 하면 된다
  (데이터는 지워지지 않는다).
- 한 기기에 사이드로드할 수 있는 앱은 3개까지다.

## 네이티브 앱 개발

요구 사항: Xcode 16.1 이상 (iOS 17.0 이상 대상). 외부 라이브러리 없음.

```sh
./Scripts/check.sh     # 프로젝트 파일 문법 + 로직 테스트 + 앱 빌드를 한 번에
./Scripts/test.sh      # 로직 테스트만 (Xcode 없이 CommandLineTools만으로도 실행됨)
./Scripts/build.sh     # 시뮬레이터 빌드만
```

`Scripts/make_icon.swift`는 1024×1024 앱 아이콘을 다시 만든다 (`xcrun swift Scripts/make_icon.swift`).

### 구조

```
GameTimer/
  GameTimerApp.swift     앱 진입점. 스토어 주입, 배경 전환 시 저장 확정
  Models/                Codable 데이터 타입과 첫 실행 기본값
  Core/                  주 계산, 문자열 포맷, 파일 저장, 상태 스토어
  Views/                 메인 / 기록 / 설정 / 항목 편집 화면
  Support/L10n.swift     화면에 나오는 한국어 문자열 모음
  Support/BiometricGate  Face ID / 기기 암호 확인
Tests/LogicTests.swift   XCTest 없이 도는 순수 로직 테스트
```

`Models/`와 `Core/`는 SwiftUI를 import 하지 않는다. 덕분에 시뮬레이터 없이 `Scripts/test.sh`로
곧바로 컴파일해 돌릴 수 있고, 날짜 계산 같은 까다로운 부분을 빠르게 확인할 수 있다.

`GameTimer/` 폴더는 Xcode의 동기화 폴더(synchronized group)로 연결되어 있다.
그 안에 `.swift` 파일을 새로 넣으면 프로젝트 설정을 건드리지 않아도 자동으로 빌드에 포함된다.
반대로 **빌드에 넣고 싶지 않은 파일은 이 폴더 밖에 두어야 한다** (`Scripts/`, `Tests/`가 밖에 있는 이유).

### 설계 메모

- **주는 저장하지 않는다.** 기록에는 시각만 남기고, 어느 주에 속하는지는 화면을 그릴 때마다
  현재 설정으로 다시 계산한다. 그래서 주 시작 요일을 바꾸면 과거 기록의 묶음도 함께 재편성된다(총합은 그대로).
- **주 경계는 반열림 구간**(`시작 <= 시각 < 끝`)으로 판정한다. `DateInterval.contains(_:)`는 끝점도
  포함하기 때문에 그대로 쓰면 경계 자정에 찍힌 기록이 두 주에 중복 집계된다. `WeekMath.interval(_:contains:)` 참고.
- **날짜 계산에 초 단위 산술을 쓰지 않는다.** 전부 `Calendar` 기준이라 서머타임이 있는 지역에서도 정확하다.
- **저장 시점은 한곳에 모여 있다.** 상태 변경은 전부 `AppStore`의 메서드를 통과한다. 기록 추가/삭제는
  즉시 저장하고, 설정 텍스트 입력은 잠깐 모았다가 저장한다.
- 저장 위치는 `Library/Application Support/GameTimer/store.json`이다. 파일이 깨지면
  `store.corrupt-<시각>.json`으로 옮겨 두고 기본값으로 시작한다.
